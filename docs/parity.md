# Parity ledger

Every feature of Kolada, where its code lives, the tests that say what it does, and where each platform stands. Read with [porting.md](porting.md): new work after 2026-10-04 also arrives through `tools/port-queue.sh`.

When you add a feature, add its row. When you port one, mark your column in the same commit.

**Code:** a shared crate (reaches every platform), or the shell (`kolada-win` on Windows: each platform builds its own). The Mac's app state, and the tests written `Mac `model/...``, are in the shared crate `crates/kolada-app/src/model/` (headless: any shell drives it; each OS's calls come in through `kolada_app::services`); what stays in `crates/kolada-mac/src/mac/` is the AppKit shell and the Mac's implementations of those services (`spell.rs`, `vision.rs`, `watch.rs`, `web.rs`, `bin.rs`, `when.rs`, `images.rs`, `fonts.rs`).
**State:** ✅ done · ◐ shared: its shared code builds and passes its tests there, the platform's own part is not built yet · — not yet · n/a does not apply.
**Linux** (`crates/kolada-linux`, the binary `kolada`; shippable 2026-10-21): winit's windows (X11 or Wayland, no title bar of their own: the chrome draws their buttons; a note's own window beside the main one), softbuffer's blit of what changed, menus drawn by the chrome (`set_drawn_menus`), the model's services in `src/linux/` (`fonts.rs`, `images.rs`, `watch.rs`, `bin.rs`, `web.rs`, `when.rs`, `spell.rs`, `clipboard.rs`, `appearance.rs`, `notify.rs`), the desktop's own file chooser (`portal.rs`), one instance (`instance.rs`), the .tar.gz install's updater (`updates.rs`), packages from `tools/linux-release.sh` (.deb, .tar.gz, AppImage). Its tests run headless (`cargo test -p kolada-linux`); built on Ubuntu 24.04 in WSL2 and tried by hand under Xvfb with xdotool (keys, the pointer, menus, dialogs, drag and drop, windows); `tools/speed-gate-linux.sh` passes there. "Wired" below: the keys and events reach the model's calls, which the model's tests cover, but not yet tried by hand.
